 0) DIE DATEIEN – was ist was?
----------------------------------------------------------------
- intern.html ............ die App selbst (das Wichtigste)
- firebase-messaging-sw.js  fuer Push-Nachrichten (gleicher Ordner!)
- firestore.rules ........ Sicherheitsregeln Datenbank (in Firebase einfuegen)
- storage.rules .......... Sicherheitsregeln Datei-Upload (in Firebase einfuegen)
- functions/ ............. Server-Funktionen (Push, Marketing-KI, Termin-E-Mails)
- wachstum.html .......... Wachstum & Betrieb: Termine, E-Mail-Automatik,
                           Franchise-Dashboard (siehe Abschnitt 10)
- MATERIAL-SHEETS.gs ..... Google-Tabellen-Sync (in Google Apps Script einfuegen)

intern.html und firebase-messaging-sw.js MUESSEN im selben Ordner liegen
und ueber HTTPS erreichbar sein (z. B. GitHub Pages).

 1) SEITE ONLINE STELLEN
----------------------------------------------------------------
1. Alle Dateien zu deinem Webspace / GitHub Pages hochladen.
2. Adresse merken, z. B. https://deinname.github.io/intern.html
3. Wichtig: Adresse muss mit https:// beginnen (nicht http://).


----------------------------------------------------------------
 2) FIREBASE GRUNDEINRICHTUNG  (console.firebase.google.com)
----------------------------------------------------------------
Projekt: formenchat

A) Anmeldung aktivieren:
   - Build -> Authentication -> "Get started"
   - Tab "Sign-in method" -> E-Mail/Passwort -> aktivieren -> Speichern

B) Datenbank anlegen:
   - Build -> Firestore Database -> "Datenbank erstellen"
   - Modus: erst Testmodus (wird gleich durch Regeln ersetzt)
   - Region: europe-west -> Aktivieren

C) Erlaubte Domains (falls Login nicht geht):
   - Authentication -> Settings -> "Authorized domains"
   - Deine Online-Adresse hinzufuegen (z. B. deinname.github.io)


----------------------------------------------------------------
 3) SICHERE REGELN EINSPIELEN (Datenbank)
----------------------------------------------------------------
1. Firestore Database -> Tab "Regeln" (Rules)
2. Gesamten Inhalt der Datei firestore.rules hineinkopieren
   (alles ersetzen)
3. "Veroeffentlichen" klicken

Diese Regeln sorgen dafuer, dass nur eingeloggte Personen Zugriff haben
und nur der Chef Aufgaben, Infos, Mitarbeiter und Dokumente verwalten darf.

 4) ERSTES CHEF-KONTO ANLEGEN
----------------------------------------------------------------
1. Im Browser die Adresse mit #chef oeffnen:
   https://deinname.github.io/intern.html#chef
2. Name, E-Mail, Passwort und den Chef-Code eingeben.
   (Chef-Code steht oben in intern.html bei  var CHEF_PIN = "...")
3. "Konto erstellen" -> du bist als Chef drin.

 5) MITARBEITER ANLEGEN  (macht der Chef in der App)
----------------------------------------------------------------
1. Unten/links auf "Chef" gehen.
2. Karte "Mitarbeiter anlegen":

----------------------------------------------------------------
 6) DOKUMENTE (kostenlos, KEIN Storage/Blaze noetig)
----------------------------------------------------------------
Funktioniert automatisch, sobald die firestore.rules aus Schritt 3
veroeffentlicht sind (die enthalten jetzt "documents" + "documentData").

So funktioniert es im Tab "Dokumente" (als Chef):
- Kleine Datei (bis ca. 0,7 MB, z. B. PDF/Bild) -> "Datei waehlen" -> direkt
  in der Datenbank gespeichert.
- Grosse Datei -> in Google Drive/Dropbox hochladen, Freigabe-Link kopieren,
  unten ins Feld "...oder Link statt Datei" einfuegen.
- Studios anhaken, optional "Als Aufgabe" -> wird in den Studios zur To-do.

Firebase Storage und die Datei storage.rules werden NICHT gebraucht.

 8) PUSH "AUCH BEI GESPERRTEM HANDY" (optional)
----------------------------------------------------------------
A) Blaze-Plan aktivieren (Console unten links "Upgrade").
   Hat ein grosszuegiges Gratis-Kontingent.
B) VAPID-Schluessel (ist schon eingetragen). Falls neu noetig:
   Projekteinstellungen -> Cloud Messaging -> "Web Push certificates"
   -> Schluesselpaar generieren -> oeffentlichen Schluessel in
      var VAPID_KEY = "..."  eintragen.
C) Server-Funktion hochladen (einmalig am PC, Node.js noetig):
      npm install -g firebase-tools
      firebase login
      cd <Ordner mit dem functions-Verzeichnis>
      firebase deploy --only functions
D) In der App oben im Chat auf "Benachrichtigungen aktivieren" tippen.
   (iPhone: vorher ueber Teilen -> "Zum Home-Bildschirm" installieren.)

 10) WACHSTUM & BETRIEB (wachstum.html) – Termine, E-Mails, Franchise
----------------------------------------------------------------
Neue eigenstaendige Seite: https://.../wachstum.html
Gleicher Login wie StudioChat (keine neuen Konten noetig).
- Termine:  Kalender pro Studio, Termin anlegen/bestaetigen/stornieren.
            Chef sieht alle 12 Studios, Mitarbeiter nur ihre eigenen.
- E-Mails:  automatische Kunden-Mails (Bestaetigung, Erinnerung ~24 Std.
            vorher, Follow-up danach, Storno-Info). Vorlagen kann der
            Chef direkt in der App im Tab "E-Mails" anpassen.
- Wachstum: Chef-Dashboard (Kennzahlen je Studio, Wettbewerber-Liste,
            Expansionsplanung). Mitarbeiter sehen diesen Tab nicht.

A) EINMALIG: firestore.rules neu veroeffentlichen
   Firestore Database -> Regeln -> kompletten Inhalt der Datei
   firestore.rules einfuegen -> Veroeffentlichen.
   (Die Datei enthaelt jetzt zusaetzlich: appointments, emailTemplates,
   studioMetrics, competitors, expansionLeads.)

B) E-MAIL-VERSAND EINRICHTEN (einmalig, ohne Kreditkarte)
   Der Versand laeuft ueber einen normalen SMTP-Zugang. Empfehlung:

   VARIANTE 1 – BREVO (empfohlen):
   + 300 Mails/Tag kostenlos, KEINE Kreditkarte noetig
   + eigene Absender-Adresse moeglich, gute Zustellbarkeit
   - einmalige Registrierung noetig (ca. 10 Minuten)
   1. Konto anlegen auf brevo.com (kostenloser Tarif reicht).
   2. Links im Menue: Einstellungen -> "SMTP & API" -> Tab "SMTP".
   3. Dort stehen Server (smtp-relay.brevo.com), Port (587),
      Login (deine Brevo-E-Mail) und ein SMTP-Schluessel
      ("SMTP-Schluessel generieren" falls noch keiner da ist).
   4. Absender-Adresse unter "Absender & IPs" bestaetigen.

   VARIANTE 2 – GMAIL MIT APP-PASSWORT (schnellster Start):
   + in 5 Minuten eingerichtet, nichts Neues anlegen
   - Absender ist die Gmail-Adresse, Limit ca. 500 Mails/Tag,
     bei viel Versand landet Gmail eher im Spam-Ordner
   1. Google-Konto -> Sicherheit -> 2-Faktor aktivieren (falls aus).
   2. myaccount.google.com/apppasswords -> App-Passwort erstellen.
   3. Werte: Server smtp.gmail.com, Port 587,
      Login = Gmail-Adresse, Passwort = das App-Passwort.

C) ZUGANGSDATEN ALS GITHUB-SECRETS HINTERLEGEN
   GitHub -> Repo -> Settings -> Secrets and variables -> Actions
   -> "New repository secret". Diese 5 Secrets anlegen:
      SMTP_HOST   z. B. smtp-relay.brevo.com  (oder smtp.gmail.com)
      SMTP_PORT   587
      SMTP_USER   Login (Brevo-E-Mail bzw. Gmail-Adresse)
      SMTP_PASS   SMTP-Schluessel (Brevo) bzw. App-Passwort (Gmail)
      MAIL_FROM   Absender-Adresse, z. B. termine@koerperformen.de
                  (bei Gmail: die Gmail-Adresse selbst)
   Die Schluessel liegen NUR auf dem Server (Cloud Functions),
   niemals im Browser-Code.

D) FUNCTIONS NEU DEPLOYEN
   Passiert automatisch, sobald die Aenderungen auf main landen
   (GitHub Actions -> "Cloud Functions deployen"). Alternativ im
   Actions-Tab den Workflow von Hand starten ("Run workflow").
   Hinweis: Solange die SMTP-Secrets fehlen, funktioniert die
   Termin-Verwaltung trotzdem – es werden nur keine Mails verschickt.

E) OPTIONAL: ZEITEN ANPASSEN
   Erinnerung: Standard 24 Stunden vor dem Termin.
   Follow-up:  Standard 3 Stunden nach dem Termin.
   Aenderbar ueber zwei weitere Zeilen im Workflow
   (.github/workflows/deploy-functions.yml, Schritt ".env schreiben"):
      echo "REMINDER_HOURS=24" >> functions/.env
      echo "FOLLOWUP_HOURS=3"  >> functions/.env
